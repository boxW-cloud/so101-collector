# SO101 采集容器 v10r11：真机可以是 SO101 或 Bobac3（Redis 数据源），前端接口不变

日期：2026-10-29（北京时间）。发布状态：v10r11 于 2026-10-29 16:04 在 Spark（`192.168.100.100`）部署，替换 v10r10，服务 healthy、采集 IDLE；Spark 当前配置不变（默认仿真，真机是 USB 上的 SO101）。

## v10r11 相对 v10r10 的变化

1. **前端不用改**：
   - 8910 的 5 个 POST（开始、重采、完成本条、结束、放弃）、对齐、视频接口、`is_sim` 的路径、参数、返回都不变。
   - 调用 SO101 的前端和数据格式不受影响。
2. **真机多了一台 Bobac3**：
   - 数据来自机器人上 Perceptor 的 Redis 采集队列（capture/v5）。
   - 只在采集期间取数据：开始采集时才开始取（先丢掉积压），结束或放弃就停，其他时候不碰队列。
   - 录制、封存、推送、完成标记都和 SO101 一样。
3. **真机用哪台只改 `.env`**：
   - `COLLECTION_REAL_ROBOT=so101|bobac3` 选真机。
   - `COLLECTION_IS_SIM` 的含义不变，仍是"默认采仿真还是真机"的过滤。
   - 原来的 `COLLECTION_REAL_ARM=on` 仍然有效，等于 `so101`。
   - 改完执行 `./start.sh`，数据源配置变了会自动重启容器（第 10.2、10.3 节）。
4. **Bobac3 的数据集用机器人自己的关节**：
   - 关节是 `joint1`~`joint6`（弧度），`robot_type` 是 `bobac3`，画面只有 `front`（400×640）。
   - SO101 的数据集仍是原来的关节名和单位（第 10.4 节）。

以下是 v10r10 的内容，仍然有效（部署相关的路径、容器名已按 2026-10-28 搬迁后的位置更新）。

## v10r10 相对 v10r9 的变化（仍然有效）

本版仍是“一个容器、同一时刻一个使用者、一个当前采集会话”。v10r10 相对 v10r9 有五处变化：

1. **真机采集**：Spark 的 USB 上接的 Seeed SO101 真实主臂直接带真实从臂（飞特 STS3215 舵机），录前方、腕部两路摄像头。前端的 5 个 POST 和 v10r9 完全相同，不传 `is_sim` 时就是真机。
2. **对齐与采集解耦**：采集不再做、也不再检查对齐。前端直接 `POST /collection/start` 就开始录制；主从臂对得上由用户自己保证，开始前先运行对齐脚本 `so101_align_follower.py`（任何一台电脑上运行，输入采集容器 IP、选真机或仿真；也可以由前端调 `POST /collection/align`）。
3. **开始和对齐都会动真实从臂**：开始后从臂立即跟随主臂（按 SDK 限速）。**调用前须在页面上确认从臂周围无人无物。**
4. **新增视频接口**（8910，免 token、可跨域）：画面列表、单帧 JPEG、WebSocket 推流（每条二进制消息是一帧 JPEG）。**前端永远只取 `camera=front`、`camera=wrist` 两路**；画的是真机还是 Isaac 仿真，由部署配置 `.env` 的 `COLLECTION_IS_SIM` 决定（第 10.3 节），前端不选。2026-10-22 起原来的 `source` 参数已去掉（传了也不起作用），单独的 8924 视频容器已下线，视频以 8910 为准。
5. **新增放弃异常批次** `POST /collection/abandon`（2026-10-21，无参数）：批次卡住或前端状态对不上时调用，容器取消当前批次、停掉设备（从臂原地保持）、把采集状态全部恢复到初始空闲，之后可以直接开始新批次（第 7 节末）。

开始采集（`id`、`name` 必填）、重采、完成本条、结束（不带参数）、202 回复、同步并写完成标记、失败无限重试，都与 v10r9 相同；默认上传目录自 2026-10-21 10:38 起是 `<部署根目录>/action-composer/data/artifacts/data_set/<id>/`（多了一层 `data_set`）；完成标记自 10:58 起是这一批文件夹里的 `<id>/.ready.json`（最后发送）。

## 1. 地址、认证与返回约定

采集 REST 基地址：`http://192.168.100.100:8910`（Spark 的有线地址）。Spark 的 WiFi 地址（2026-10-28 起为 `192.168.0.215`，以前是 `192.168.0.198`）同样可用，两个地址是同一个容器。

采集 REST 和视频接口都**不需要 token**：前端直接按 IP 调用，不发送 `Authorization`，不先登录，也不需要 Cookie 或 `csrf_token`。有 JSON 正文时只设置：

```http
Content-Type: application/json
```

容器为采集请求绑定后台配置的固定 operator 与项目；前端不提交 `project`。无凭据跨域调用支持 `GET`、`POST`、`OPTIONS`，采集与视频接口的回复都带 `Access-Control-Allow-Origin: *`；前端使用 `credentials: "omit"`，不携带 Cookie。

| 地址或链路 | 本版认证方式 |
|---|---|
| 采集容器 8910 的本指南 5 个 POST 及已登记 v8/v9 采集兼容接口、状态/操作查询 | 免 Bearer token，由后台固定 operator/project 处理 |
| **8910 视频接口 `/collection/video*`（本版新增）** | **免 token、可跨域，只读画面，不碰机器人** |
| 同一采集服务的 `/healthz`、`/openapi.json` | 可直接读取，不传 token |
| `/v2/*` 管理接口 | 原有 Bearer 认证保留 |
| 数据同步服务器（rsync over SSH） | 账号 + 密码（或 SSH 私钥），由容器部署配置（`.env`）提供，前端不传 |
| 容器与 ROS 适配器之间 | 内部认证与签名保留，前端无需参与 |
| 8920 测试工作台 | 仍使用原 Cookie/CSRF 流程（走 v8 接口）；新前端直接调用 8910 |

> 前端所在电脑如果开了系统代理（如 Clash 一类），请把 `192.168.*` 加入代理绕过。经过代理的 POST 可能拿到空正文的 502，直连才是容器真实的 400/409 回复。

### 容器部署配置

部署人员只需要改 `.env`（第 10 节），前端都不用提交：镜像、容器名、4 个宿主机目录、同步服务器，以及**真实主从臂的控制板序列号、摄像头路径和默认采集目标**。

所有 POST 通过基本检查并持久化受理后，立即返回 **HTTP 202**。完整正文统一为：

```json
{
  "ok": true,
  "result": {
    "accepted": true,
    "message": "已接收，后台执行中"
  }
}
```

返回字段含义：

```json
{
  "ok": "boolean，true 表示本次请求已被接口接受，不代表后台操作完成。",
  "result": {
    "accepted": "boolean，固定 true，表示容器已持久化接收命令。",
    "message": "string，受理提示；本版固定为：已接收，后台执行中。"
  }
}
```

**6 个 POST 全部是短接口。** 容器只做参数检查、把命令写进持久化记录就立即回复（毫秒级，与 v10r9 相同），不等设备、不等封存、不等同步：

| 接口 | 回复 | 后台还在做的事 |
|---|---|---|
| 对齐 `align`（独立，采集前由用户自己做） | 立即 202 | 打开两只臂和摄像头，从臂慢速走到主臂姿态并保持（实测约 5～17 秒，离得越远越久） |
| 开始 `start` | 立即 202 | 开始录制，从臂跟随主臂（不对齐、不检查相差） |
| 重采 `redo` | 立即 202 | 废弃当前轮次、重新开始录制 |
| 完成本条 `complete` | 立即 202 | 本地保存当前条、开始下一条 |
| 结束 `finish`（不带参数） | 立即 202 | 停止与封存，从臂原地保持，释放串口；之后推送、校验、写完成标记 |
| 放弃异常批次 `abandon`（不带参数） | 立即 202 | 取消命令、停掉设备会话（从臂原地保持）、本批标为已放弃（不上传）、释放占用；空闲时约几毫秒，有会话要停时几秒 |

前端只需要自己生成并保存本批次的 `id`（第 3 节），不需要保存会话、条目、请求或操作 ID。**页面只能显示“已接收”，不能把 HTTP 202 显示为“已保存”“已对齐”或“已同步”。** 同步是否完成，以服务器上这一批文件夹里出现 `.ready.json`（即 `<id>/.ready.json`）为准（第 7 节）。

每次 POST 都会被视为一次命令尝试；容器会拒绝冲突操作，但不保证识别跨网络的重复请求。控制 POST 不应配置自动重试。

## 2. 接口总表

| 操作 | 路径 | 参数 | 后台行为 |
|---|---|---|---|
| 对齐（独立） | `POST /collection/align` | 空正文或 `{}` | 对齐部署配置的默认目标（Spark 为真实从臂）：从臂慢速走到主臂姿态并保持，不录制。采集前由用户自己做；带 `request_id` 的写法可指定真机/仿真并返回 `operation_id`（第 4 节） |
| 开始采集 | `POST /collection/start` | **`id`、`name` 必填**；`description`、`is_sim`、`fps`、`ros` 可选 | 用上游 `id` 创建当前批次并开始录制，从臂跟随主臂；不对齐、不检查主从臂相差 |
| 重采本条 | `POST /collection/redo` | 空正文或 `{}` | 废弃当前未提交轮次，重新录制当前逻辑条 |
| 完成本条并继续 | `POST /collection/complete` | 空正文或 `{}` | 本地保存当前条，自动开始下一条，暂不发送 |
| 结束本批并自动同步 | `POST /collection/finish` | 空正文或 `{}`（`upload_url` 可选，一般不传） | 停止、保存非空当前条、封存整批，推到 `<部署根目录>/action-composer/data/artifacts/data_set/<id>/`，校验后写完成标记 |
| 放弃异常批次 | `POST /collection/abandon` | 空正文或 `{}`，**不接受任何参数** | 取消当前批次和所有未完成命令，从臂原地保持，本批不上传，采集状态全部恢复到初始空闲 |
| 画面列表 | `GET /collection/video` | 无 | 当前画面来源（真机或仿真，只读）和 front、wrist 两路是否有新画面、每路的地址 |
| 单帧画面 | `GET /collection/video/<camera>.jpg` | `<camera>` 为 `front` 或 `wrist` | 返回一张 JPEG |
| 视频推流 | `GET /collection/video/ws`（WebSocket） | `camera`、`fps` 可选 | 先发一条 JSON 文本，之后每有新画面发一条二进制 JPEG |

无需前端传入 `project`、`robot_id`、`robot_revision`、`calibration_revision`、`config_revision`、`scene_id`、`scene_revision`、`workspace_confirmed`，也不传同步服务器、串口或摄像头。

**一批真机采集的顺序：** （用户事先运行对齐脚本，主臂保持不动）→ 页面现场确认 → 开始 → 主臂示教 → 完成本条（可多次）/ 重采 → 结束。下一批用新的 `id` 开始。

## 3. 开始采集

**最小请求（前端只发这两个字段即可）：**

```http
POST /collection/start HTTP/1.1
Host: 192.168.100.100:8910
Content-Type: application/json

{
  "id": "dataset-3f9c2a7e5b1d4c6e",
  "name": "将试管放入试管架"
}
```

**全部允许参数的含义：**

```json
{
  "id": "string，必填。上游生成的本批次唯一 ID：1～128 位，只能是字母、数字、_、.、-，并以字母或数字开头。它就是容器里的会话 ID 和数据集 ID，也是服务器上的文件夹名 <目录>/<id>/。每个 id 只能开始一次。",
  "name": "string，必填，非空且不能全部为空格。用户输入的示教任务名称/文本。",
  "description": "string，可选，任务描述，允许空字符串。",
  "is_sim": "boolean，可选。不传时按容器部署配置的默认目标（Spark 当前为 Isaac 仿真）；false 表示部署配置的那台真机（SO101 真实从臂或 Bobac3，第 10.2 节）；true 表示 Isaac 仿真从臂。一般不传。",
  "fps": "integer，可选，1～30，使用原采集频率配置规则；不是机器人运动速度，也不保证实际达到指定帧率。",
  "ros": "object，可选，只能声明已经登记的公开 ROS 配置的相同子集，不能修改 Topic、QoS、设备绑定或提交密钥。"
}
```

开始必须提交 JSON 对象，不能使用空正文。`is_sim` 必须是 JSON 布尔值，不能是字符串 `"true"`。

**关于 `id`：**

- 同一个 `id` 已经开始过一批，再用会返回 **409 `ID_ALREADY_USED`**。下一批必须用新的 `id`，服务器上也就是新的文件夹。
- 请求在受理前被拒绝（参数错误、忙碌 `BUSY`）时，`id` **没有被占用**，可以原样重试。
- 已经返回 202 之后后台启动失败（例如摄像头没画面），这个 `id` 已被占用，需要换新的 `id`。

**关于对齐（2026-10-21 09:27 起，对齐与采集解耦）：** 8910 的开始**不做对齐，也不检查对齐**：不要求事先调过 `align`，不在开始时自动对齐，开始和换下一条时也不检查主从臂相差多少。**主从臂对得上由用户自己保证**：

- 开始前由用户运行对齐脚本 `so101_align_follower.py`（或前端调 `POST /collection/align`，第 4 节），让从臂走到主臂姿态；然后主臂保持不动，再点开始。
- 开始后从臂**立即跟随主臂**。如果主从臂没对齐，从臂会从当前位置朝主臂姿态追过去：速度仍受 SDK 限制（每次最多离实测位置 3°、每秒最多 30°，5 fps 时约 15°/s），**这段追赶会录进数据**。
- **`start` 会让真实从臂运动**（真机是 SO101 时），开始按钮要做现场确认（第 4 节）。真机是 Bobac3 时采集容器只读数据、不控制机器人，机器人由平台控制。
- 8910 的开始不再返回 `ALIGNMENT_REQUIRED`。
- 8920 测试工作台和旧版 v9 接口的规则没变（仍要求先对齐、仍检查相差）。

**关于真机和仿真：** 不传 `is_sim` 时采默认目标，默认目标由部署配置 `.env` 的 `COLLECTION_IS_SIM` 决定（Spark 当前为 `true`，即仿真；第 10.3 节）；真机用哪台由 `COLLECTION_REAL_ROBOT` 决定（第 10.2 节）。前端一般不传 `is_sim`，切换由部署人员改 `.env`。

**HTTP 202 完整返回：** 同第 1 节。

## 4. 对齐主臂与真实从臂（独立，采集前由用户自己做）

**最小请求：**

```http
POST /collection/align HTTP/1.1
Host: 192.168.100.100:8910
Content-Type: application/json

{}
```

没有业务参数，真正空正文也接受，不传 `is_sim`。**这个命令会让真实从臂运动。** 页面上的对齐按钮请做二次确认，提示操作者确认从臂周围无人无物、手在电源旁、对齐期间主臂保持静止。

本接口与采集解耦：采集不会调用它，也不检查有没有对齐过。

**带结果的写法（指定真机或仿真，可以查对齐结果）：** 正文带 `request_id`（每次新生成，字母数字开头，字母、数字、`_`、`.`、`-`）和 `is_sim`：

```http
POST /collection/align HTTP/1.1
Host: 192.168.100.100:8910
Content-Type: application/json

{"request_id": "align-3f9c2a7e5b1d4c6e", "is_sim": false}
```

返回 HTTP 202，`result` 里有 `operation_id`。之后 `GET /collection/operations/<operation_id>`（免 token）查结果：`state` 为 `QUEUED`/`RUNNING` 表示还在进行；`SUCCEEDED` 且 `result.aligned`、`result.holding` 都为 `true` 表示对齐完成并保持；`FAILED`/`INTERRUPTED` 时 `error` 写明原因（例如仿真 `Registered leader input expired` = 主臂输入没连上）。`is_sim: true` 只动 Isaac 仿真从臂。

**对齐脚本 `so101_align_follower.py`：** 用的就是上面带结果的写法，只用 Python 标准库，任何电脑上都能运行（不用登录 Spark、不依赖 docker）。运行后在命令行里依次输入：采集容器 IP（或 `IP:端口`，端口默认 8910）→ 真机 `r` 或仿真 `s` → 现场确认 `yes`；然后等对齐结果。上次输入的 IP 和选择记在各用户主目录的 `.so101_align.json`，下次直接回车。也可以用参数：`--ip 192.168.100.100 --real --yes`。

这个现场确认（对齐和开始都要做）由前端页面自己做（弹窗或勾选框，例如 8920 工作台上的“我在现场，从臂周围已清空……”“我已在现场确认工作空间安全，可以开始采集。”），**不是 8910 的接口参数**：8910 的 `align`、`start` 都没有 `workspace_confirmed` 字段，带上会返回 400 `INVALID_FIELDS`。工作台把勾选结果作为 `workspace_confirmed` 发给它自己那条通道，与 8910 无关。

后台依次：打开两只臂的控制板 → 核对舵机标定和登记时一致 → 等两路摄像头出画面 → 检查从臂舵机温度 → 从臂限力、限速上电，从当前位置慢速走到主臂姿态 → 到位后**原地保持（不卸力）**。不开启录制。

安全限制（容器内固定，前端不能改）：

| 项 | 限制 |
|---|---|
| 速度 | 目标每秒最多变化 30°；每次最多离实测位置 3°（5 fps 时实际约 15°/s） |
| 单步兜底 | 发给舵机的目标离实测位置超过 8° 直接拒绝 |
| 力矩 | 各关节力矩上限 15%～50%（夹爪 50%） |
| 温度 | 任何舵机超过 55°C 拒绝运动 |
| 对齐合格 | 六个关节都在主臂姿态 6° 以内（夹爪按 0～100 的开合度计） |
| 主臂 | 从头到尾只读，不上电、不写入 |

对齐完成后从臂原地保持；之后什么时候开始采集都可以（主臂别动）。采集过程中从臂跟随主臂，速度同样受上表“速度”“单步兜底”限制，**主臂请慢慢动**。完成一条后从臂原地保持；开始下一条时不检查主从臂相差，从臂直接继续跟随主臂。结束采集后从臂原地保持、串口释放；从臂不会自己卸力。

**HTTP 202 完整返回：** 同第 1 节。

没有必填参数，真正空正文也接受。这一批放到同步服务器的

```text
<部署根目录>/action-composer/data/artifacts/data_set/<id>/
```

`action-composer/data/artifacts/data_set` 这段是固定的（2026-10-21 10:38 起；之前是 `action-composer/data/artifacts`，没有 `data_set`）。服务器上 `<部署根目录>/action-composer/data/artifacts` 必须已存在且同步账号可写；`data_set` 这一级不存在时容器推送前自动建（只建这一级，上一级不存在则照常报错重试，不会在服务器上建出一串目录）。

`<部署根目录>` 是 `.env` 的 `COLLECTION_SYNC_DEPLOY_ROOT`（Spark 为 `/home/lxk/dev2`，2026-10-21 改正；之前误配为 `/home/unitree/deploy`）。可选参数 `upload_url`（兼容 v10r8 前端）的规则不变：不传、`null` 或空字符串用默认目录；传了必须是同步服务器上的绝对目录，这一批改放到 `<upload_url>/<id>/`（`upload_url` 的最后一级不存在时同样自动建）。

**这是短接口：** 容器把结束命令写进持久化记录后立即返回 202，下面的步骤全部在后台进行，每一步都有持久化记录，容器重启后继续：

1. 停止当前采集，保存非空当前条；从臂原地保持，释放两只臂的串口。
2. **封存**：视频、Parquet、元数据全部写完后形成不再改动的数据集目录。
3. **准备目录、推送数据**：`<目录>` 的最后一级（`data_set`）不存在就建；rsync 到 `<目录>/<id>/`（`manifest.json` 先不发），中断的大文件下次续传。
4. **逐文件校验**：按内容 checksum 比对服务器上的每个文件与本地是否一致。
5. **推送 `manifest.json`**，最后写完成标记 `<目录>/<id>/.ready.json`（在这一批的文件夹里，文件名固定为 `.ready.json`）。

**失败重试：** 推送任何一步失败（断网、服务器不可达、密码错、没配部署根目录、目录不可写、校验不一致）都由容器自动重试，5 秒起、之后翻倍、最长约 2 分钟一次，**没有次数上限，直到成功**。修正问题后执行 `./apply-env.py` 即可，不需要重新结束采集，也不用重启容器。

收到 202 后可以离开页面。后台停止和封存完成后（通常几秒）即可对齐、开始下一批（用新的 `id`）；在此之前对齐/开始会返回 409 `BUSY`，稍后再点即可。

**HTTP 202 完整返回：** 同第 1 节。

### 放弃异常批次（2026-10-21 新增）

**请求（没有参数）：**

```http
POST /collection/abandon HTTP/1.1
Host: 192.168.100.100:8910
```

空正文或 `{}` 都可以；带了任何字段返回 400 `INVALID_FIELDS`。免 token、可跨域。立即返回 HTTP 202（正文同第 1 节）。

**什么时候用：** 批次卡住了（开始/结束一直不完成、`start` 一直返回 `BUSY`、容器重启后留下没收尾的批次），或者前端和容器的状态对不上、想直接从头开始时。没有异常时调用也无害，相当于确认一次“初始状态”。

**容器在后台做的事（通常几秒内完成）：**

1. 取消所有排队和执行中的命令（新版和旧版接口的都算），这些命令的结果记为“已放弃”，不会再执行完。
2. 停掉所有设备会话：录制中的停止录制，对齐中的停止对齐。**从臂原地保持，不卸力**；串口释放。30 秒内停不下来的会话直接让从臂停住并断开连接。
3. 当前还没结束的批次标为“已放弃”（`ABANDONED`）：**不上传**，不再算当前批次；已录的数据留在容器本地，不删除。这个 `id` 不能再用来开始。
4. 释放机器人占用，清掉所有对齐记录。之后状态为 IDLE，可以直接用新的 `id` 开始。

**不受影响的：** 已经结束（`finish` 已完成封存）、正在推送或已推送的批次照常推送；同步服务器配置、数据目录、相机画面都不变。

**放弃进行中**（通常几秒）调其他接口会返回 409 `BUSY`，稍等再试即可。每次放弃的结果记在容器内 `/data/collection-abandon-last.json`（取消了哪些命令、停了哪些会话、放弃了哪些批次、释放了哪些占用、有没有错误），供运维查看。

## 8. 视频接口（本版新增）

**前端永远只有两路画面：`camera=front`（前方）和 `camera=wrist`（腕部）。** 画的是真机还是 Isaac 仿真由容器的部署配置决定（`.env` 的 `COLLECTION_IS_SIM`，第 10.3 节），前端不用选，也选不了；真机和仿真的画面不会同时出现。2026-10-22 起原来的 `source` 参数已去掉，旧前端还带着 `source=...` 也不会出错，只是不起作用。

- 真机（`real`）：容器里有一个摄像头常驻进程，一直开着两路真实摄像头（每路 640×480、15 fps）；录制和视频接口用的是**同一份画面**，互不抢设备，什么时候打开都有画面（不用先开始采集）。
- 仿真（`sim`）：Isaac 仿真渲染的画面（原有的仿真预览），转成 JPEG 后用同样的接口提供，前端写法完全一样。

三个接口都是 GET，**免 token、可跨域**，只读画面，不会让机器人运动。

| 参数 | 取值 | 默认 |
|---|---|---|
| `camera` | `front`（前方）或 `wrist`（腕部） | `wrist` |
| `fps` | 只用于 WebSocket，1～30 的整数，最多每秒推这么多帧 | `10` |

### 8.3 WebSocket 推流

```text
ws://192.168.100.100:8910/collection/video/ws?camera=front&fps=10
```

**一路画面一个连接**；前方和腕部各开一个连接。客户端不需要发送任何消息。连上后：

1. 先收到一条 **JSON 文本** `hello`（`source` 只读，告诉前端这条连接画的是真机还是仿真）：

```json
{"type": "hello", "source": "real", "camera": "front", "fps": 10, "fresh": true, "width": 640, "height": 480, "format": "image/jpeg"}
```

   画面暂时没有时 `fresh` 为 `false`、`width`/`height` 为 `null`，并带 `message` 说明原因；连接不会断，画面一恢复就开始推。

2. 之后每有新画面就收到一条**二进制消息，内容是一帧完整的 JPEG**。只推新帧（同一帧不重复推），最多每秒 `fps` 帧，也不会超过画面源本身的帧率（真实摄像头 15 fps，Isaac 仿真预览约 5 fps）。实测 `fps=10` 时真机每路约 9～10 帧/秒、每帧 9～15 KB，两路合计约 0.3 MB/s；仿真每路约 4.7 帧/秒、每帧 12～29 KB。

3. 画面中断（超过 1 秒没有新帧）和恢复时各收到一条 JSON 文本：

```json
{"type": "status", "fresh": false, "message": "摄像头 front 的画面已经 1.2 秒没有更新"}
{"type": "status", "fresh": true}
```

4. 参数错误或人数满时，先收到一条 JSON 文本 `error`，随后容器关闭连接：

```json
{"type": "error", "code": "INVALID_FPS", "message": "fps 必须是 1～30 的整数"}
```

| 关闭码 | 含义 | 前端处理 |
|---|---|---|
| 4400 | 参数错误（`INVALID_CAMERA`、`INVALID_FPS`） | 改参数，不要重连 |
| 4429 | 同时连接超过 16 个（`TOO_MANY_VIEWERS`） | 关闭不用的页面后再连 |
| 4503 | 部署配置的视频来源写错了（`VIDEO_SOURCE_INVALID`） | 提示联系部署人员；2 秒后重连即可 |
| 其他（网络断开、容器重启） | — | 2 秒后自动重连 |

部署人员切换真机/仿真后，**已经连着的 WebSocket 不会自动切换**，重连后才是新来源（页面刷新一下即可）；单帧和画面列表下一次请求就是新来源。

容器每 15 秒发一次 WebSocket ping，浏览器会自动回应，前端不用处理。

### 10.3 真机还是仿真：`COLLECTION_IS_SIM`（2026-10-25）

默认采仿真还是真机只改 `.env` 的**一项**（含义和 v10r10 相同；Spark 当前为 `true`，即仿真）：

```sh
# false = 真机（COLLECTION_REAL_ROBOT 选的那台），true = Isaac 仿真（真实主臂带仿真从臂）
COLLECTION_IS_SIM=true
```

它同时决定三件事：

| | `COLLECTION_IS_SIM=false`（真机） | `COLLECTION_IS_SIM=true`（仿真） |
|---|---|---|
| 前端开始采集、对齐不传 `is_sim` 时的目标 | `COLLECTION_REAL_ROBOT` 选的真机（SO101 或 Bobac3） | Isaac 仿真从臂 |
| 8910 视频 front、wrist 两路 | SO101：真实摄像头；Bobac3：Redis 的 front（只在采集期间有画面） | Isaac 仿真画面 |
| Spark USB 上的真实主臂（SO101） | 带真实从臂 | 容器自动起一个只读主臂的进程，每秒 20 次把主臂姿态送给仿真从臂 |

切换步骤：先确认没人在采集（`curl -s http://127.0.0.1:8910/collection/status` 为 `IDLE`），把 `.env` 里的 `COLLECTION_IS_SIM` 改成 `true` 或 `false`，然后执行：

```sh
cd /home/nvidia/so101-collection && ./start.sh
```

`./start.sh` 看到配置变了会自动重启容器，重启时不会让臂运动。约一分钟后确认：`curl -s http://127.0.0.1:8910/collection/status` 返回的 `target_type` 为 `physical`（真机）或 `simulation`（仿真）。

- 值只能是 `true` 或 `false`，写错时 `./apply-env.py` 报错退出；不写这一项时，选了真机（`COLLECTION_REAL_ROBOT`）就是真机，否则是仿真。`COLLECTION_IS_SIM=false` 必须选一台真机，否则报错。
- **Spark 上的仿真遥操作靠 USB 上的 SO101 主臂驱动**，只有 `COLLECTION_REAL_ROBOT=so101` 时主臂才接给仿真。选 `bobac3` 时仿真从臂没有主臂输入，所以采 Bobac3 时请同时设 `COLLECTION_IS_SIM=false`。
- 原来的 `COLLECTION_DEFAULT_MODE`、`COLLECTION_VIDEO_SOURCE` 两项已去掉；`.env` 里还留着的话 `./apply-env.py` 会提示可以删掉，它们不再起作用。
- 仿真时主臂必须插着并且舵机上电；拔了或没电时，仿真对齐、仿真采集会在后台以 `SOURCE_STALE`（主臂输入过期）失败。
- 仿真时主臂串口被仿真主臂输入占着，这时显式传 `is_sim=false` 做真机对齐或采集会以 `DEVICE_BUSY` 失败；要采真机就把开关改回 `false` 并重启。
- 仿真时主臂超出仿真关节范围的姿态会被夹在范围内（例如大臂在限位附近时为 -98°）。
- 视频画面来源存在 `config/video.json`，容器每次请求都读，所以只想换视频画面时 `./apply-env.py` 之后不重启也会生效；但默认采集目标和主臂接到哪边要重启后才变，用 `./start.sh` 会自动处理。

### 10.4 Bobac3：Redis 数据源（v10r11）

`COLLECTION_REAL_ROBOT=bobac3` 时，真机数据来自 Bobac3 上 Perceptor 的 Redis 采集队列（capture/v5）。`.env` 里这一组：

```sh
COLLECTION_REDIS_HOST=192.168.0.233
COLLECTION_REDIS_PORT=6379
COLLECTION_REDIS_DB=0
COLLECTION_REDIS_PASSWORD=           # 有密码就填，写到 config/redis.password（600）
COLLECTION_REDIS_ROBOT_ID=bobac3-capture
COLLECTION_REDIS_ROBOT_TYPE=bobac3   # 写进数据集的 robot_type
COLLECTION_REDIS_JOINTS=joint1,joint2,joint3,joint4,joint5,joint6   # 数据集里的关节名，按顺序
COLLECTION_REDIS_CAMERAS=front=400x640                              # 相机名=高x宽
COLLECTION_REDIS_FPS=4
```

切到 Bobac3：设 `COLLECTION_IS_SIM=false`、`COLLECTION_REAL_ROBOT=bobac3`，然后执行 `cd /home/nvidia/so101-collection && ./start.sh`。

**怎么取数据：**

- **只在采集期间取：**
  - 前端 `start` 时，容器先丢掉队列里的积压，然后用 BRPOP 消费 `collection_observation_queue` 和 `collection_action_queue`。
  - `finish` 或 `abandon` 后停止。其他时候不碰队列，所以不采集时队列会涨到 1000 条上限、Perceptor 随即停止出数，这是正常的，下次 `start` 会先丢掉积压。
- **图片马上取：** 每条观测给的图片 key 收到就 GET（图片 60 秒过期），JPEG 640×400。
- **动作事件不进数据集：** 按 `event_id` 去重、按 `process_id + action_id` 合并成一条动作记录，存在容器的 `/data/redis-capture/<会话>/`（`actions_merged.json`、`summary.json`）。
- **不控制机器人：** Bobac3 由平台控制，采集容器只读数据。

**数据集里是什么：**

| 数据集里 | 内容 |
|---|---|
| `robot_type` | `bobac3`（`COLLECTION_REDIS_ROBOT_TYPE`） |
| `observation.state` 6 维 | Perceptor 的 `joint1`~`joint6` 原样写入，名字和单位都是机器人自己的（弧度），不用 SO101 的名字 |
| `observation.images.front` | Bobac3 的前置相机，400×640；没有 `wrist` |
| `action` 三列 | 占位：当前实测状态 |
| 每帧时间 | Perceptor 的采样时刻（换算到本机时钟），不是送达时刻 |
| 每帧来源信息 `meta/source-frames/` | Perceptor 的 `process_id`、`observation_id`、原始关节值、图片 key、`data_gap_count` |
| `manifest.json` | `joint_names`=joint1~6，`units`=rad×6，`joint_mapping` 记录 SDK 内部换算 |

- **夹爪：** Bobac3 的末端夹爪目前不在 Perceptor 的状态里，没有采。
- **默认帧率：** 4 帧/秒（Bobac3 出数约 4.8 Hz）。
- **训练容器还不能训练这些数据：** 它目前只认 SO101 的关节名，训练 Bobac3 的数据需要另外改训练容器。

**使用注意：**

1. **供数开关：**
   - 开始采集前，平台（DM）要先打开 Redis 的 `collection_enabled`。没打开时 `start` 在后台失败，原因写明"供数开关 collection_enabled 没有打开"。
   - 和其他后台失败一样，要先 `finish`（几秒内结束，状态 `EMPTY`）或 `abandon` 再开始下一批。
   - 结束时建议先 `finish` 再关供数；先关也能正常结束，这时停止确认用的是最后一条观测，来源信息里标 `restamped_after_hold`。
2. **送达停顿：**
   - Perceptor 采样均匀，但送达偶尔会晚约 1 秒后一起到，这种情况能正常处理。
   - 超过 1.4 秒没有任何新观测时，当前条判为供数中断，录制停止；`finish` 照样保存已录的部分，也可以 `abandon` 放弃整批。
3. **视频：** `GET /collection/video` 的 `front` 只在采集期间有画面，`wrist` 没有。

只读查看队列和供数开关（不消费）：

```sh
docker exec so101-collection /opt/runtime/bin/python -m deployment_runtime.redis_capture peek
```

## 11. 立即拒绝与后台失败

请求未通过基本检查时直接返回非 202。示例：

```json
{
  "ok": false,
  "error": {
    "code": "ALIGNMENT_REQUIRED",
    "message": "A successful alignment from this service instance is required"
  }
}
```

字段含义：

```json
{
  "ok": "boolean，false 表示接口立即拒绝本次请求。",
  "error": {
    "code": "string，机器可读的错误码。",
    "message": "string，错误原因；实际文字以服务返回为准。"
  }
}
```

常见错误码：

| HTTP | code | 含义 |
|---|---|---|
| 400 | `INVALID_FIELDS` | 开始采集缺 `id` 或 `name`，或带了不认识的字段（对齐不接受任何字段） |
| 400 | `INVALID_ID` | `id` 格式不对 |
| 400 | `INVALID_NAME` | `name` 为空或全是空格 |
| 400 | `INVALID_UPLOAD_URL` | 结束采集带了 `upload_url`，但不是合法的服务器绝对目录 |
| 409 | `ID_ALREADY_USED` | 这个 `id` 已经开始过一批 |
| — | `ALIGNMENT_REQUIRED` | 2026-10-21 09:27 起 8910 不再返回（采集不检查对齐）；旧版 v9 接口和 8920 工作台仍会返回 |
| 409 | `BUSY` | 已有采集或操作在进行，或正在放弃异常批次（稍等几秒再试） |
| 409 | `NO_CURRENT_COLLECTION` | 没有正在进行的采集（重采/完成/结束时） |
| 400 | `INVALID_CAMERA` | 视频的 `camera` 不是 `front` 或 `wrist` |
| 409 | `VIDEO_UNAVAILABLE` | 单帧画面：这一路超过 1 秒没有新画面 |
| 503 | `VIDEO_SOURCE_INVALID` | 部署配置 `config/video.json` 写错了（由部署人员按第 10.3 节执行 `./apply-env.py`） |

WebSocket 的错误见第 8.3 节。

请求已受理之后发生的失败记录在容器内部，不能再改变之前返回的 HTTP 202。真机相关的后台失败：

| code | 含义 | 处理 |
|---|---|---|
| `DEVICE_NOT_CONNECTED` | 找不到主臂或从臂的控制板 | 检查 USB 线和控制板电源 |
| `DEVICE_BUSY` | 串口被别的程序占着 | 关掉其他占用串口的程序（如 `so101-follower-direct`）；`COLLECTION_IS_SIM=true` 时主臂被仿真主臂输入占着，要采真机见第 10.3 节 |
| `SOURCE_STALE` | 仿真对齐/采集等不到主臂输入（“Registered leader input expired”） | 检查主臂是否插着、舵机是否上电；`COLLECTION_IS_SIM` 须为 `true`（第 10.3 节） |
| `CALIBRATION_CHANGED` | 舵机标定和登记时不一样 | 重新标定过的话重启容器 |
| `CAMERA_STALE` | 某一路摄像头没有画面 | 检查摄像头接线和 USB 口（第 10.2 节） |
| `OVERHEAT` | 从臂舵机超过 55°C | 停一会儿再对齐 |
| `SOURCE_STALLED`（Bobac3） | 开始时：供数开关 `collection_enabled` 没有打开；录制中：超过 1.4 秒没有新观测 | 让平台打开供数；先 `finish` 或 `abandon` 当前批次，再用新 `id` 开始 |
| `SOURCE_FAILED`（Bobac3） | 连不上 Bobac3 的 Redis | 检查网络和 `.env` 的 `COLLECTION_REDIS_HOST` / `PORT` |
| 对齐失败（对齐脚本或 `align`） | 摄像头没画面、控制板没接上、主臂在对齐中被移动、舵机过热等 | 排除原因后再运行一次对齐脚本 |

连接不到容器可能表现为连接错误、超时或代理的 5xx，不能统一当作“容器已经收到但执行失败”。

## 13. 第三方前端最小调用示例

以下示例直接访问 Spark 的采集 REST，不获取 token，不轮询采集状态。每次用户操作只调用对应函数一次；HTTP 202 只显示“已接收”。可以直接打开的完整示例页见 `SO101双机位视频前端示例-20261020.html`。

**采集控制（与 v10r9 相同）：**

```javascript
const collectionBase = "http://192.168.100.100:8910";

async function collectionPost(action, payload) {
  const options = {
    method: "POST",
    credentials: "omit"
  };
  if (payload !== undefined) {
    options.headers = { "Content-Type": "application/json" };
    options.body = JSON.stringify(payload);
  }
  const response = await fetch(`${collectionBase}/collection/${action}`, options);
  const data = await response.json();
  if (!response.ok || data.ok !== true) {
    throw new Error(`${data.error?.code ?? response.status}: ${data.error?.message ?? ""}`);
  }
  return data.result; // { accepted: true, message: "已接收，后台执行中" }
}

// 以下为各按钮的独立调用示例，不要把它们一次性连续执行。
function alignFollower() {
  // 可选。真实从臂会运动：调用前在页面上二次确认“从臂周围无人无物”
  return collectionPost("align"); // 无正文、不传 is_sim
}
function startCollection(id, name, description = "") {
  // 真实从臂会立即跟随主臂运动：调用前在页面上二次确认（对齐由用户事先运行对齐脚本完成）
  return collectionPost("start", { id, name, description }); // id 由上游生成，每批一个
}
function redoCurrentEpisode() {
  return collectionPost("redo");
}
function completeCurrentEpisode() {
  return collectionPost("complete");
}
function finishCurrentBatch() {
  return collectionPost("finish"); // 数据到 <部署根目录>/action-composer/data/artifacts/data_set/<id>/
}
function abandonBatch() {
  // 放弃异常批次：本批不上传，采集状态全部恢复到初始空闲；从臂原地保持
  return collectionPost("abandon"); // 无正文、无参数
}
```

**视频（只有 front、wrist 两路；一路一个 WebSocket，断线自动重连）：**

```javascript
// 打开一路画面，显示在 <img> 上。返回关闭函数。camera 只能是 "front" 或 "wrist"
function openCamera(img, { camera = "wrist", fps = 10, onStatus = () => {} } = {}) {
  const url = collectionBase.replace(/^http/, "ws") +
    `/collection/video/ws?camera=${camera}&fps=${fps}`;
  let ws;
  let stopped = false;
  function connect() {
    ws = new WebSocket(url);
    ws.binaryType = "blob";
    ws.onmessage = (event) => {
      if (typeof event.data === "string") {          // 文本：hello / status / error
        const msg = JSON.parse(event.data);
        onStatus(msg.type === "error" ? msg.message : msg.fresh ? "有画面" : (msg.message || "画面中断"));
        return;
      }
      const frame = URL.createObjectURL(event.data); // 二进制：一帧完整 JPEG
      img.onload = () => URL.revokeObjectURL(frame);
      img.src = frame;
    };
    ws.onclose = (event) => {
      if (!stopped && event.code !== 4400) setTimeout(connect, 2000); // 4400 = 参数错误，不重连
    };
  }
  connect();
  return () => { stopped = true; ws.close(); };
}

// 双机位：前方、腕部各一路（真机还是仿真由容器部署配置决定，前端不选）
const closeFront = openCamera(document.querySelector("#front"), { camera: "front" });
const closeWrist = openCamera(document.querySelector("#wrist"), { camera: "wrist" });
// 页面关闭或切走时调用 closeFront()、closeWrist()

// 当前画面来源（只读，可用于页面提示）："real" 或 "sim"
async function videoSource() {
  const response = await fetch(`${collectionBase}/collection/video`, { credentials: "omit" });
  const data = await response.json();
  return data.result.source; // 两路状态在 data.result.cameras.front / .wrist
}

// 单帧：可直接当图片地址
// <img src="http://192.168.100.100:8910/collection/video/front.jpg">
async function snapshot(camera) {
  const response = await fetch(`${collectionBase}/collection/video/${camera}.jpg`, { credentials: "omit" });
  if (!response.ok) throw new Error((await response.json()).error.message); // 409 = 暂时没有画面
  return response.blob(); // image/jpeg
}
```

若使用 Axios 等请求封装，同样不要附加登录 token、Cookie 或自动重试；WebSocket 断线重连按上面的 2 秒间隔即可。
